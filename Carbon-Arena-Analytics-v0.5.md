# Carbon Arena - Analytics Appendix v0.5

Analytics describe observable transfers, not additional game rules. Version 0.5 separates the two carbon sources: ordinary ground regeneration and new production inside working trees. No proportional source-lineage model is implemented.

## Events

Existing v0.4 events retain their payloads: `move`, `harvest`, `pickup`, `absorption`, `theft`, collision `drop`, `destroy`, `plant`, `expiry`, `sale`, `purchase`, `purchase_rejected`, `regeneration`, and `strategy_failure`. Every event has `turn`, global cumulative `seq` and `type`. Coordinates remain zero-based.

New event:

```json
{"turn":4,"seq":3,"type":"tree_generation","team":"Red","tree":1,"amount":4}
```

The example sequence number is illustrative. `tree` is the global tree identifier; `amount` is the actual configured production rate. Events are emitted after all absorption and before every expiry, in increasing tree ID. Generation zero emits no production events. New trees do not emit generation on planting turn. The fiftieth working tick emits generation before that tree's expiry. Expiry events are emitted in increasing tree ID after generation finishes globally.

Absorption moves ground into storage; generation creates new storage. Pickup moves storage into cargo earlier in the turn. Expiry moves remaining storage onto ground, available for harvesting or absorption from the next turn. Planting and purchases spend cash only. A destroy event describes a loss; its associated theft/drop performs the cargo transfer, so never count destroy cargo twice. Existing `collisionEvent` references and vehicle-loss versus encounter distinctions remain unchanged.

## Turn and final summaries

An audit contains summaries from turn 0 through `throughTurn`. The last entry is the final/current summary; no second competing final-counter schema is needed. All supply and sale counters are cumulative.

| Field | Meaning |
| --- | --- |
| `ground`, `stored`, `inTransit` | Current ground, tree storage and living-vehicle cargo |
| `sold` | Carbon delivered and sold by both teams |
| `initial` | Initial ground carbon in normal matches |
| `regenerated` | Ground regeneration only |
| `treeGenerated` | Carbon generated by all working trees |
| `treeGeneratedByTeam` | `{Red, Blue}` tree-production totals; sum equals `treeGenerated` |
| `totalAccounted` | `ground + stored + inTransit + sold` |
| `expectedTotal` | `initial + regenerated + treeGenerated` |
| `carbonError` | `totalAccounted - expectedTotal`, required to be zero |
| `cash` | `{Red, Blue}` cash balances |
| `expiryReleased` | Carbon transferred from expiring storage onto ground; not a new source |
| `losses`, `lossesByTeam`, `collisions` | Vehicle losses and encounters by empty tie, cargo tie and theft |

Internal `generatedCarbon` keeps its original ground-only meaning. New `treeGeneratedCarbon` and per-team `treeGenerated` accumulate production. These counters are exposed in audits/summary UI, not as private accounting additions to the strategy snapshot. Strategies can see actual settings and public generation events.

For each team in a standard match starting with no trees:

`absorbed + treeGenerated = pickup + expiredStorage + finalStored`

Measure `absorbed` directly from absorption events and check this identity separately. The equivalent subtraction identity can check accounting, but does not independently verify every absorption event. Preloaded test fixtures add their initial storage to the left-hand side. Similarly, fixtures with initial cargo or storage must initialize total carbon accordingly; ordinary matches start with only ground carbon.

Cash is `initialCash + sold - plantingSpend - purchaseSpend`, with list-price events counted once. Tree storage, vehicles, and undelivered cargo have no terminal cash credit.

## Viewer and replay interpretation

Resource flow shows cumulative ground and tree supply separately, plus per-team production and conservation error. Timeline scrubbing recomputes every displayed counter from recorded decisions at the selected turn. Exported audits use the viewed turn; replay exports retain the complete decision list. Rules 0.4 records are rejected by the v0.5 viewer ; the original project retains the older viewer separately.

Historical experimental audits sometimes fold tree production into their `regenerated` field. Preserve those bytes and interpret them through their own adapter protocol and provenance. Do not relabel an old file as v0.5. The earlier lab interleaves generation and expiry by tree; the v0.5 public event contract completes generation globally before expiry, so raw event order is intentionally different even when physical outcomes agree.

## Scope of external analysis

Global conservation and per-team storage/cash ledgers do not uniquely attribute eventual sales to generated, absorbed, stolen or expired carbon. Ground can mix all sources and ownership can change through collection and theft. An optional future lineage tool would need exact inventory accounting (for example rational proportional shares), newly generated source cohorts, and event-order processing. It must avoid summing overlapping pickup/expiry cohort reports as independent supply.

Delivery latency based only on completed trips excludes unfinished/lost trips. Mirror-policy cash and reversal counts may reflect symmetric avoidance rather than ordinary-match efficiency. The old duel's spending decomposition remains historical accounting, not a causal no-planting experiment. Those analytics are not changed by the generation patch.

Joint verification should report which physical fields, counters, economics and events actually match, the code hashes and seeds, and each resolver's independent conservation result. An economic-only match must not be reported as raw-event identity. See `docs/VALIDATION.md` for this publication's execution coverage.
